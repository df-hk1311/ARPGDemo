# ARPGDemo 产品设计文档（MVP）

- 文档版本：v0.1
- 更新日期：2026-09-12
- 目标平台：Windows / Unreal Engine 5.8
- 开发方向：C++ 为主，蓝图负责表现层

## 1. 产品定位

一款单机 ARPG 战斗 Demo，用于展示 UE5 C++ 开发能力、战斗系统设计能力和工程实现质量。

第一版聚焦一个稳定、可重复体验的战斗闭环：

> 主菜单 -> 进入竞技场 -> 完成波次战斗 -> 胜利或失败 -> 结算 -> 重新挑战或返回主菜单

目标单局时长为 3～5 分钟。

## 2. 核心设计原则

- 优先保证战斗手感、流程完整和版本稳定。
- 第一版不制作成长、装备和存档等外围系统。
- 通过敌人组合和波次变化提供有限的重复可玩性。
- 核心规则使用 C++ 实现，蓝图主要用于动画、特效、音效和 UI。
- 所有核心功能必须能够在打包版本中运行。

## 3. 主要功能

### 3.1 主菜单

- 开始游戏。
- 退出游戏。
- 第一版暂不包含设置、账号和存档功能。

### 3.2 竞技场与流程

- 一张封闭竞技场地图。
- 玩家出生点和敌人刷新点。
- 固定三波战斗，全部敌人消灭后进入下一波。
- 第三波结束后判定胜利，玩家死亡则判定失败。
- 支持重新挑战和返回主菜单。

### 3.3 玩家角色

- 基础移动和第三人称镜头。
- 普通攻击三段连招。
- 闪避及无敌帧。
- 一个主动技能。
- 生命值、受击、死亡和重置状态。

### 3.4 战斗系统

- 攻击与受击判定。
- 伤害计算、生命值扣除和死亡。
- 受击硬直、击退和命中停顿。
- 攻击、闪避和技能之间的状态限制。
- 技能冷却和资源消耗。
- 使用动画通知驱动攻击判定和战斗反馈。

### 3.5 敌人与波次

第一版包含近战和远程两种普通敌人：

- 近战敌人：追击玩家并进行近距离攻击。
- 远程敌人：保持距离并发动远程攻击。

固定三波配置：

1. 三个近战敌人。
2. 两个近战敌人和一个远程敌人。
3. 两个远程敌人和一个强化近战敌人。

敌人 AI 只需支持感知、追击、攻击、保持距离和死亡状态。

### 3.6 UI 与结算

- 玩家生命值。
- 技能冷却状态。
- 当前波次和剩余敌人数量。
- 胜利或失败结果。
- 击杀数量、战斗耗时、重新挑战和返回主菜单。

第一版不制作 Boss 专属血条。

### 3.7 战斗反馈

- 攻击、受击和死亡动画。
- 命中音效和技能音效。
- Niagara 命中特效。
- 受击闪白或材质反馈。
- 镜头震动和少量命中停顿。

## 4. 技术方向

第一版使用轻量 C++ 组件完成闭环，包括角色控制、属性、战斗、波次、敌人 AI、游戏流程和 UI 数据接口。

蓝图负责动画蓝图、动画蒙太奇、Niagara、材质、UMG 布局和关卡摆放。

GAS 暂不作为 MVP 的强制依赖。战斗闭环稳定后，再评估是否将属性和技能系统迁移到 GAS。

## 5. 非目标

- 经验、等级、技能树和成长选择。
- 装备、背包、商店和掉落。
- 存档和读档。
- 多个关卡、玩家角色或职业。
- 复杂任务、剧情和对话。
- 复杂 Boss 战和 Boss 血条。
- 联机和网络同步。
- 高级伤害类型、抗性和异常状态系统。

## 6. MVP 验收标准

1. 打包后可以从主菜单进入竞技场。
2. 玩家可以移动、连招、闪避并使用一个主动技能。
3. 近战和远程敌人能够执行基本战斗行为。
4. 三波战斗能够正确生成、推进和结束。
5. 玩家死亡和敌人清空都能进入正确的结算结果。
6. 重新挑战可以完整重置局面，不残留上一局状态。
7. 核心战斗逻辑具有可重复执行的测试或验证流程。
8. 打包版本没有明显崩溃或阻塞性错误。
